Guide · Multi-runtime

Run Claude Code and Codex in separate boxes

Running two runtimes at one problem is a useful trick and a security requirement at the same time, because a box holding both vendors' credentials is a laundering path waiting for a prompt injection.

By Koukyosyumei Reading time 5 min Tags Multi-runtime · Comparison · Credentials
The gotcha up front. Create both boxes from the same base, in the same sitting. Each pins its base revision immutably at creation, so two boxes created an hour apart across a merge are describing changes to different trees and the comparison stops meaning anything.

1. Export both host tokens

~/my-project
$ export ANTHROPIC_API_KEY=sk-ant-...
$ export OPENAI_API_KEY=sk-...

Both stay on the host. Each box gets a base-URL override and a per-run dummy, and the host-side proxy injects the real credential into outbound requests for the runtime that box is scoped to.

2. Create one box per runtime

~/my-project
$ h5i box . --name try-claude --profile agent-claude
$ h5i box . --name try-codex  --profile agent-codex

agent-claude grants Claude's own HOME state and Anthropic egress. agent-codex grants Codex's state and OpenAI egress. Neither can see the other's credential or reach the other's API.

That split is the security part. A single box holding both would let a prompt-injected session read the other runtime's token and spend it against a host the allowlist already permits, which is exactly the move the allowlist exists to prevent.

3. Run them

~/my-project
$ h5i box shell try-claude   # in one terminal
box$ claude

$ h5i box shell try-codex    # in another
box$ codex

4. Compare, then take one

~/my-project
$ h5i box ls
$ h5i box compare try-claude try-codex
$ h5i box export try-codex --out ./review

Because both pinned the same base at creation, the two diffs describe changes to the same tree and the comparison is honest. Drop any box whose report shows denied egress you cannot explain before you compare the diffs at all.

There is no verifier. h5i does not rank the two for you. A model judging model output produces a confident ranking, which is the exact failure mode running two agents was supposed to avoid, so the judgement stays yours.

FAQ

Why two boxes instead of one box with both runtimes?

Because a box holding both vendors' credentials lets a prompt-injected session read the other runtime's token and spend it against a host the allowlist already permits. Separate boxes are how the credentials stay separate.

Do the API keys go into the boxes?

No. Both stay on the host. Each box gets a base-URL override and a per-run dummy token, and a host-side proxy injects the real credential into outbound requests for the runtime that box is scoped to.

Does h5i pick the better result?

No. There is no verifier and no score. A model judging model output produces a confident ranking, which is the failure mode running two agents was meant to avoid, so h5i gives you two receipts and two diffs and leaves the judgement to you.
