Warm the dependency cache so boxes start fast

A disposable environment stops being disposable when creating one costs four minutes of npm ci. One cache per project and ecosystem fixes that, without giving two boxes a shared writable surface.

By Koukyosyumei Reading time 5 min Tags Performance · Caching · Setup
The gotcha up front. refresh needs a project-declared profile whose egress is the registry hosts and nothing else. Without one it refuses, and prints the profile ready to paste rather than creating a box whose fetch could not have worked.

1. Declare a registry-only profile

.h5i/env.toml
[profile.fetch]
isolation = "supervised"

[profile.fetch.net]
mode   = "deny"
egress = ["registry.npmjs.org"]

Registry hosts and nothing else. This profile runs an install step with no agent in it, so the narrowest possible egress is exactly right.

2. Populate the cache

~/my-project
$ h5i box cache refresh npm

This creates a dedicated box that runs the install step alone, with no agent inside. The thing that populates a shared artefact is the most constrained process in the system, which is the correct way round.

3. Check it

~/my-project
$ h5i box cache ls       # caches for this project, and whether they are stale
$ h5i box cache mounts   # exactly what a box would get

Each cache is keyed by a digest of that ecosystem's lockfiles. Change the lockfiles and the key no longer matches, so the cache is listed as stale and never handed to a box. Not refreshed automatically, not used with a warning. Packages resolved for a different dependency set are a silent wrong answer, and a slower box beats a mystery.

4. Use it

~/my-project
$ h5i box .   # mounts the cache read-only, automatically

Read-only costs nothing in correctness, because every package manager falls back to fetching what it cannot find. On a hit you save the download; on a miss the tool behaves normally. What it buys is that no mutable surface is ever shared between an agent box and anything else.

5. Remove one when you are done

~/my-project
$ h5i box cache rm npm
The cache accelerates fetching and says nothing about what was fetched. A poisoned package is cached like any other. Keeping bad packages out is the egress allowlist's job on the way in, and the receipt's job afterwards.

FAQ

How do I make h5i boxes start faster?

Populate a warm dependency cache with h5i box cache refresh <ecosystem>. It is keyed per project and ecosystem by a digest of the lockfiles, and every agent box then mounts it read-only. Cold install is the difference between a twenty-second box and a four-minute one.

What happens when I change a lockfile?

The cache key no longer matches, so the cache is listed as stale and never handed to a box. Packages resolved for a different dependency set are a silent, hard-to-explain wrong answer, and a slower box is the better outcome.

Why is the cache mounted read-only?

Because a writable shared cache is a mutable surface two boxes can both reach, so one could plant something the next picks up. Read-only costs nothing, since every package manager falls back to fetching what it cannot find.

Why does refresh refuse without a declared profile?

Because it needs egress narrowed to the registry hosts and nothing else, and guessing would create a box whose fetch could not have worked. It prints the profile ready to paste, so the error is the fix.
