Guide · Credentials

Give a box your Claude Code config without your credentials

Your agent keeps its settings and its credentials in the same directory. A box has to take the first and must not take the second, and it does that by shape rather than by a list of names you have to maintain.

By Koukyosyumei Reading time 5 min Tags Credentials · Configuration · Security
The gotcha up front. The seed is one-way. A setting the agent changes inside a box stays there and disappears with the box. If you want a preference to persist, change it on the host before creating the next one.

1. Create an agent box

~/my-project
$ h5i box . --profile agent-claude

The agent-claude profile grants Claude's own HOME state and Anthropic egress and nothing else. agent-codex does the same for Codex. Use the pinned variants rather than bare agent when you know which runtime you are running, because a box holding both runtimes' credentials would let an injected session spend the other one's token.

2. Know what was copied, and what was not

The box gets its own writable copy of the agent's HOME, seeded once from the real one and never written back. The default is copy; two lists subtract from it.

SubtractedExamplesWhy
Large session treesprojects/, sessions/, todos/, history.jsonl, shell snapshots, host logsSize. A fresh box does not need your transcripts, and copying less host data in is strictly more private.
Credential-shaped files, at any depthcredentials*, .netrc, id_rsa, id_ed25519, known_hosts, .env, secrets.json, keyring, gh_tokenSecurity. Matched by shape, not location.
By extension, anywhereanything ending .pem, .key, .p12, _rsa, _ed25519Catches deploy-prod_ed25519, which no name list would have.

The runtime's own API token is deliberately kept, because the agent cannot function without it and the profile already scopes egress to that runtime's API. Everything else authenticates through the host-side proxy, which never lets the credential into the box at all.

3. Verify from inside

box
box$ ls ~/.claude              # settings are here
box$ ls ~/.ssh 2>&1          # not granted at all
ls: cannot access '/home/agent/.ssh': No such file or directory
box$ cat ~/.claude/.credentials.json 2>&1
cat: …/.credentials.json: No such file or directory

4. Check the declared secret grants

~/my-project
$ h5i box secrets <name>   # dry-run resolution; fingerprints, never values
Shape matching is a floor, not a ceiling. A credential in a file named notes.txt is copied in like anything else. The credential proxy exists because file filtering alone was never going to be enough.

FAQ

Does a box get my Claude Code credentials?

It gets a filtered copy of your agent's HOME. Credential-shaped entries are dropped by shape at any depth, including anything ending .pem, .key, .p12, _rsa or _ed25519. The runtime's own API token is kept, because the agent cannot function without it and the profile scopes egress to that runtime's API.

Do config changes made inside a box persist?

No. The seed is one-way: copied in once and never written back. Change a preference on the host if you want the next box to have it.

Why use agent-claude rather than agent?

Because a box scoped to one runtime holds one runtime's credentials. If a box got both, a prompt-injected Claude session could read the other runtime's token and spend it against a host the allowlist already permits.
