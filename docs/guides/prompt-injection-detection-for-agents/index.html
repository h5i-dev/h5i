Guide · Security

Contain a prompt-injected agent

Detection is low-recall by construction, so this guide skips it. Assume the injection worked, then write down in a config file exactly what the compromised agent is able to reach.

By Koukyosyumei Reading time 6 min Tags Security · Prompt injection · Policy
The gotcha up front. A net.egress allowlist needs supervised, container or microvm. Set it on process and h5i refuses the profile, because the process tier's network namespace is all-or-nothing and accepting the field would put a claim in the manifest that nothing enforces.

1. Check what your host can enforce

~/my-project
$ h5i box probe

The probe runs a functional self-test rather than reading capability bits, because a hardened kernel or an AppArmor profile can deny confined exec while Landlock, seccomp and userns all report present.

2. Write the profile

.h5i/env.toml
[profile.review]
isolation = "supervised"

[profile.review.fs]
read  = ["~/.npm"]      # the cache, read-only
write = []              # $WORK is already writable

[profile.review.net]
mode   = "deny"
egress = ["registry.npmjs.org"]   # the only destination that exists
unix   = false

[profile.review.resources]
mem   = "4G"
procs = 256
wall  = "30m"

Every list is fail-closed: unset grants nothing. Keep write empty. Every entry you add there is a path an injected agent can modify.

3. Understand what each line stops

What the injection wantsWhat it meets
Read ~/.ssh or a neighbouring repoThe filesystem allowlist. Never granted, and Landlock is allowlist-only, so there is nothing to widen from inside.
POST the tree somewhereDefault-drop nftables in a private netns, with DNS pinned by a hosts file, so an IP literal fails like a hostname does.
Steal a token from the environmentNothing to steal. The model key stays on the host; the HOME seed strips credential-shaped files.
Use the other runtime's credentialRuntime scoping. Use agent-claude or agent-codex, never both in one box.
Write into your working treeNo write path out. h5i box export is a step you take.

4. Read what was refused

~/my-project
$ h5i box export review --out ./review
$ head -6 ./review/report.md

# Denied egress
  paste.example.invalid:443   refused (not in net.egress)   x3

The refusal is observed host-side, by the proxy's own log, and lands under the host-env-run lane. The agent does not report it and cannot suppress it, because the receipt log sits outside every grant the policy hands out.

What this does not stop. The agent can still put your private source into a model prompt. Containment bounds what it touches on your machine and on the network; the model channel is a separate control, meaning a self-hosted model or no model egress at all.

FAQ

Can I detect prompt injection instead of containing it?

Not reliably. A pattern matcher catches the phrasings you thought of, and a model-based classifier reads the attacker's text and can be addressed by it. Run detection as triage if you like, and put the security claim somewhere the attacker's text has no vote.

Why does h5i refuse net.egress on the process tier?

Because that tier's network namespace is all-or-nothing: it can offer deny or host and cannot honour a domain allowlist. Accepting the field would record a claim nothing enforces, so the profile is refused and you are told to use supervised, container or microvm.

Where does the refusal get recorded?

In the box's receipt, under the host-env-run lane, from the allowlist proxy's own log. The agent does not report it and cannot suppress it, because the receipt log is a sibling of the box's spool and sits outside every grant.
