Guide · Receipts

Find out what actually ran in a box

Not what the agent says it did. What a supervisor watched it do, what a proxy refused it, and which of those two grades of evidence each line came from.

By Koukyosyumei Reading time 5 min Tags Receipts · Observability · Review
The gotcha up front. Every record carries a lane, and the lane decides what the record is worth. host-env-run and viewer are host-observed. tee-shim and inbox-capture are the box's own account of itself. Read them as different grades of evidence, because they are.

1. The event log

~/my-project
$ h5i box log fix-auth

2. The policy that was actually enforced

~/my-project
$ h5i box status fix-auth
$ h5i box capabilities fix-auth --json

status reports what was enforced, not what was requested. A limit the host cannot hold is marked with * and explained rather than listed as enforced, which matters on macOS at the kernel tiers where mem and procs cannot be held at all. It also reports base drift.

3. One run, in full

~/my-project
$ h5i box inspect fix-auth --capture c4a91f

The capture id comes from the log or from a row in h5i ui. Each record carries the command (secret-redacted), the exit code, wall and CPU time, peak RSS, the git tree it ran against, the policy digest in force, and, when relevant, an egress summary and what the browser reported.

4. Everything, as files

~/my-project
$ h5i box export fix-auth --out ./review
$ jq '.[] | select(.source == "host-env-run")' ./review/receipt.json

What to look for

  • Denied egress, first. It is the only signal that makes a claim about the boundary, and the proxy observed it host-side.
  • A gap between lanes. A long host-observed process with nothing claimed during it, or more commands reported than exits observed. Not proof of anything, and worth a question.
  • Work that never happened. A build with no test run, under a summary saying the tests pass, is a four-second catch.
The claim stops here. An agent can stage extra records or stop writing them. Both are visible as a gap against host-observed exits, and that visibility is the whole claim. It does not extend to the log being complete.

FAQ

How do I see what commands an agent ran in a box?

h5i box log <name> for the event log, h5i box inspect <name> --capture <id> for one run in full, and h5i box export to write the whole receipt out as JSON. None of it needs the agent to cooperate, because none of it is a hook.

What is the difference between the lanes?

host-env-run and viewer are observed by h5i from outside: exits and resource usage from the supervisor's wait4, egress from the allowlist proxy's log. tee-shim and inbox-capture come from inside the box and are its own account of itself.

Why does h5i box status mark some limits with an asterisk?

Because it reports the policy actually enforced. On macOS at the kernel tiers, memory and process-count limits cannot be held, so h5i declines to apply them and marks them rather than claiming enforcement it does not have.
