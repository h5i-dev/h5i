Feature Overview

A browser you can read back. A boundary when you want one.

Driving a browser and observing one are different jobs, and most tools only do the first. h5i's engine is the HTTP client, so the request log is a decision record written before the bytes moved rather than a trace assembled beside the network. Sessions run here by default, with no containment claimed; one flag places the same session inside a sandbox, which adds a witness outside the browser. One Rust binary, no daemon, no SaaS.

What is an auditable browser session?

A lifetime that holds one page state, one cookie jar, one request log and one policy, addressed by an id. Every request it makes is checked against that policy and written down before the bytes move, and a fetch that cannot be recorded does not happen.

Session = page + jar + policy + fail-closed log.
Box = the sandbox a session, an agent and a dev server can be placed in.

A session on the host is not sandboxed and h5i does not say it is. It is not a defence against a targeted kernel exploit below the microvm tier, and it does not classify what a page says. It records what was reached and limits what can be.

Browsingwhat the agent read, and what it actually reached
h5i browser open · snapshot · click · requests · close
A request log that cannot be incomplete
The engine is the HTTP client, so the order is fixed: check the policy, write the decision, then touch the wire. If the record cannot be written the fetch is refused, so there is no path that reaches the network quietly. Denials are logged with their reason, so the log shows what was attempted and not only what succeeded, and a redirect out of the allowlist is refused at the hop rather than followed and explained afterwards.
a request that is not in the log did not happen.
br_7k2xqa
One noun, whatever is underneath
A session is the only thing an agent has to learn. start prints an id, every verb names it, close ends it. The process that renders the page, the port it listens on and whether it is inside a box are all implementation, and none of them appear in a command. That is what lets --in <box> change the security posture without changing a single verb or a single answer.
placement is a flag, not a second product.
engine-claimed · host-observed
Two lanes, never merged
A host session's log is fail-closed, complete, and still the browser describing itself: h5i calls that engine-claimed and prints it on every status line. A boxed session whose box enforces an egress allowlist at its boundary is additionally seen from outside the thing being described, and only then is it host-observed. A box that lets the browser reach the whole network corroborates nothing and does not earn the upgrade.
being in a box is not evidence; enforcement outside the engine is.
h5i browser audit
One timeline, and it says who is speaking
The request log is the network layer on its own. The audit merges it with the verbs the agent asked for, the moments a human took the controls, and the ending, ordered across all three. The lanes are never merged: the engine's rows are its own account of itself, the handovers and the lifecycle are h5i's, written from outside, and every row carries which. A log h5i could not read is reported as unavailable, because an empty timeline and an unwatched session are different findings.
“was a human driving when that form was submitted” is a question about two logs at once.
exit 69
Endings are written down
A session directory outlives the session, so closed, died, expired and evicted stay answerable afterwards, and an id is never reused. A verb sent to a session that is not live is refused with its own exit code and never silently restarted, because an agent whose retry cannot tell “the session is gone” from “the click did not work” quietly starts a second browser and loses both the page and the record of losing it. --restore inherits the storage into a new id, with the inheritance recorded.
a gap in the record is a state, not an absence.
h5i browser take · release · login
A person can take the wheel
The agent holds control by default and a human takes it rather than asking: mutating verbs pause, reads keep working because watching never collides, and handing control back forces a re-snapshot since the page moved underneath. For a boxed session the pause is enforced, because every verb is carried in from the host and the host is outside the box. For a host session it is advisory, and take says so rather than letting you assume otherwise.
the arrangement decides whether a lock is a boundary; h5i names which one you have.
UNTRUSTED PAGE CONTENT
Page text stays data
A snapshot arrives inside a fence that tells the model the text within is information about a page, not instructions. Escape sequences never survive the relay, because ESC in a page title is a page repainting the terminal it is printed into. Strings, arrays and nesting are capped with the truncation stated in the value rather than performed quietly, and page JavaScript is off unless asked for, which removes the delivery channel outright.
h5i does not classify what a page says; it limits what a persuaded agent can reach.
Collaborationwhat the agents can tell each other, and what they still cannot do
h5i forum create · attach · revoke · close
A forum the sandboxes cannot reach
Two agents in two boxes have no way to reach each other. They post to threads the host owns, and the host decides what each box gets to see. A box has exactly two forum-shaped holes in it, and both already existed: a read-only inbox in, and the single writable spool that was already drained after every session. No socket, no port, no token. create, attach, revoke and close are refused inside a box no matter who asks, and that refusal is a courtesy: the refs those verbs write are outside every grant the box holds.
the strongest access control here is the absence of an API.
sender · role · box · policy digest ← stamped by the host
The box writes what, never who
The staged record has fields for a thread, a kind, a body and attachments, and no field for a sender, a role, a box id or a policy digest. Those are stamped by the host from the environment the record was found in, so a record that names itself "sender": "human" does not have that field read, because the field does not exist in the format. You can watch it happen: h5i forum read puts the host's knowledge on the line above the fence and one agent's claim inside it.
identity is not validated on the way in; it is written on arrival.
h5i forum create --ceiling <profile>
A ceiling every participant is confined under
A thread names a profile every box on it must be confined under. At attach, the box's enforced policy, read from its digest-verified policy.resolved.toml rather than a worktree file an agent could have edited, is checked across every dimension that widens reach: network mode and egress, secret grants, authenticated egress, filesystem read and write grants, AF_UNIX, loopback ports and host-side secret extractors. A box that exceeds any of them is refused, not quietly re-confined to fit. attach also refuses a workspace-tier box outright, because that tier enforces nothing.
a message can change what a peer decides; it cannot change what that peer can do.
h5i forum remote · --branch-refs · h5i forum wait
Git as the transport and the durable history
Forum state is Git refs, synced under an append-only union, so a deleted conversation comes back from any honest clone on the next sync, and --branch-refs publishes it where the forge's own protection rules apply. There is no service to run on either side: an agent's whole notification story is h5i forum wait, which polls a directory the box already has mounted, and on the host the process already supervising a running box moves its mail. Refusals are recorded rather than swallowed: a revoked sender's post still lands, carrying the refusal.
host-observed is evidence, peer-claimed is testimony, and rows are labelled either way.
Containmentwhat the agent cannot reach, decided before it starts
h5i box . · --pr · <url> · --new
A disposable box, shaped by where the code came from
Your own repository gives you a real git worktree on its own branch, sharing the object store, so h5i box apply can land the work back locally. A URL, a pull request or --new gives you a detached box: its own repository, yours neither read nor written after creation, and the inherited origin remote dropped so the box arrives holding no network handle. The policy is resolved, written out and hashed before any state exists on disk, so an unsatisfiable request fails closed rather than leaving half a box behind.
external code can never land by momentum: apply refuses on a detached box.
isolation = workspace | process | supervised | container | microvm
Five tiers, each labelled with what it honestly claims
Landlock, seccomp and namespaces on Linux; Seatbelt on macOS; rootless Podman for portability; and a microVM with its own kernel through microsandbox. auto picks the strongest the host can run, and an explicit tier fails closed rather than downgrading, because a silent downgrade puts a claim in the record the run never had. h5i box probe runs a functional self-test rather than reading capability bits.
the tier you asked for is the tier you got, or creation refused.
[profile.X.net] egress = […]
Egress allowlists, named by OSI layer
supervised enforces at L3/L4: default-drop nftables in a private netns, DNS pinned by a hosts file, and a seccomp-notify gate on socket() that denies AF_NETLINK so the ruleset cannot be flushed from inside. container enforces at L7 with a CONNECT proxy, which binds proxy-respecting tooling only. microvm evaluates it in the guest's own network stack. Same field, three different guarantees, and h5i says which one you got.
"egress control" is never one word here: the claim is stated per tier.
[[profile.X.auth]] · h5i box secrets
Credentials that never enter the box
The model API key stays on the host; a reverse proxy injects it into outbound requests, scoped per runtime, so a Claude box cannot reach the OpenAI credential. Any other service is declared the same way: a host, a host-side credential variable, and the base-URL variable the client reads. The per-box HOME copy strips credential-shaped entries at any depth, including anything ending .pem, .key, _rsa or _ed25519.
a prompt-injected agent has no reusable token to read or exfiltrate.
Evidenceobserved from outside, stored where the box cannot reach it
h5i box export <name> --out ./review
The output gate
Three files. patch.diff, path-validated against symlink escapes, a nested .git and agent-introduced gitlinks. report.md, ordered by how much you should trust each section, with denied egress attempts first and the agent's own proposal last. receipt.json, every observed execution with the policy digest that was enforced. It refuses to overwrite a non-empty directory, and secret redaction and size caps apply to all three.
the box has no write path to your machine; getting work out is a step you take.
h5i box log · status · inspect --capture
A sealed execution receipt
An append-only JSONL log per box. The box's entire write window under its own directory is its spool; the receipt log and its payloads are siblings of that spool, outside every grant. The box stages a record and the host ingests it, so there is no path from inside to a record the host already wrote. Exits and resource usage come from the supervisor's wait4, egress from the allowlist proxy's own log.
the record is generated from observation, not from the agent's account of itself.
source: host-env-run | viewer | tee-shim | inbox-capture
Every record names who observed it
Host-observed and box-claimed evidence never blur into one number, because the lane is a required field on every record and the console labels every row with it. An agent can stage extra records or stop writing them; both are visible as a gap against host-observed exits, and h5i does not claim more than that.
you can tell testimony from observation without trusting either.
h5i ui
The box console, read-only by construction
The whole fleet on one screen: every box with its tier and status, the policy actually enforced, and a flight recorder of one row per receipt across five lanes. Red means the egress allowlist refused a destination and nothing else is ever red; amber means look at this; grey means the evidence is weak. Every route is a GET, so there is no mutating surface to guard. Loopback only, with a session token kept in memory so no box can read it.
nothing on the screen is a score, and the console cannot drive a box.
Working in itthe parts that make autonomy actually usable
agent-browser · h5i box view · h5i browser take
A browser in the box, with two interfaces
Chrome and a fresh profile live inside, so nothing you are logged into on the host is logged in there. The agent drives it; you watch the same viewport and take the controls when you want. The stream port is never published: h5i enters the box's network namespace by pid, connects from inside, and hands the socket back out. --term draws the page in your terminal and binds nothing at all.
frames flow out always; input flows in only for the control-lock holder.
h5i box cache refresh · ls · mounts
Warm dependency caches
Cold install is the difference between a twenty-second box and a four-minute one. One cache per project and ecosystem, keyed by a digest of that ecosystem's lockfiles; a cache whose key no longer matches is stale and never handed to a box. Mounted read-only, which costs nothing because every package manager falls back to fetching what it cannot find, and written only by a box with no agent inside and egress narrowed to the registries.
no mutable surface is ever shared between an agent box and anything else.
h5i skill install · show · path
The agent skill, embedded in the binary
The skill is compiled in at build time, so it cannot document flags the installed binary does not have. That matters more for agents than for people: an agent acts on stale documentation without hesitating, then reports that your tool is broken. The in-box agent gets it the same way, from the binary already in the box, so nothing is baked into an image and nothing is copied from host to box.
the documentation an agent reads is an artefact of the build, not a file that rots separately.

Use Cases

The box in action

Five workflows where containment changes what is possible, not just what is safer.

01
Put two agents on one problem without pairing their authority
A worker and a reviewer, in separate boxes, on one thread. The forum is a Git ref the host owns; from inside a box it is not merely unwritable, it is invisible.
~/my-project 
$ h5i box create alpha --profile agent-claude
$ h5i box create beta  --profile agent-codex

$ h5i forum create "fix the auth refresh race" --ceiling agent
$ h5i forum attach alpha --as alpha-worker  --role worker
$ h5i forum attach beta  --as beta-reviewer --role reviewer

# inside alpha: it can say things, and it holds nothing to say them with
box$ h5i forum post f04d --kind FINDING "the CAS at auth/refresh.rs:118 is not atomic"
box$ ls ~/.git/refs/h5i/forum
ls: cannot access '/home/agent/.git/refs/h5i/forum': No such file or directory

# inside beta, a different box on a different profile, reading the same thread
box$ h5i forum read f04d
  2. FINDING alpha-worker (worker)  08-20 14:09
     box env/claude/alpha · host-observed
     │ the CAS at auth/refresh.rs:118 is not atomic

Neither box holds a forum credential, and neither wrote the identity line above the fence. Run a forum →

02
Review a pull request by running it
Checking out a stranger's branch used to mean handing its install scripts your shell. A detached box makes running it the cheap option instead of the risky one.
~/my-project 
$ h5i box --pr 1234
  created box pr-1234 · detached · own repository · origin remote dropped

$ h5i box shell pr-1234
box$ npm ci && npm test      # lifecycle scripts run in here, not on your machine
box$ exit

$ h5i box export pr-1234 --out ./review
$ head -6 ./review/report.md

# Denied egress
  telemetry.vendor.invalid:443   refused (not in net.egress)   x7

Seven refused connections from a branch whose description says it fixes a date-formatting bug. Run the review →

03
Let an agent run with permissions off, safely
Inside a box, permission mode is a convenience setting rather than a boundary. The boundary is the policy that was hashed before the box existed.
~/my-project 
$ h5i box . --profile agent-claude
$ h5i box shell fix-auth
box$ claude --dangerously-skip-permissions

# it still cannot read what was never granted
box$ cat ~/.ssh/id_ed25519
cat: /home/agent/.ssh/id_ed25519: No such file or directory

# and it still cannot reach a host nobody declared
box$ curl -s https://paste.example.invalid
curl: (7) Failed to connect: refused by egress policy
04
Watch the page the agent is driving, then take over
The stream port is never published. h5i enters the box's network namespace by pid, connects from inside, and hands the socket back out.
~/my-project 
box$ agent-browser stream enable
box$ agent-browser open http://localhost:3000

$ h5i box view fix-auth          # loopback-only forward, per-box token
$ h5i box view fix-auth --term   # draw it here instead; binds nothing

$ h5i browser status fix-auth
  control: agent   refs: fresh
$ h5i browser take fix-auth      # immediate; the agent's @refs go stale

Handing control back invalidates every page reference the agent held, so it must re-snapshot before acting and acting first is refused rather than mis-clicked. Use the control lock →

05
Find out what this machine can actually enforce
A functional self-test, not a feature probe. The required bits can all be present while a hardened kernel still denies confined exec.
~/my-project 
$ h5i box probe
── Host isolation capabilities ──
  os           = linux
  mechanism    = landlock+seccomp
  landlock_abi = 3
  userns       = true
  seccomp      = true
  tty-injection= blocked at the kernel tiers, possible at isolation=workspace
  container    = podman
  microvm      = none

  claim workspace  satisfiable = yes
  claim process    satisfiable = yes
  claim container  satisfiable = yes (needs rootless Podman + profile container.image)
  claim microvm    satisfiable = no  (needs microsandbox `msb` + host virtualization)
  process tier runnable = yes

tty-injection is h5i measuring something it declines to assert: on Linux it is your kernel's setting, on macOS it is the Seatbelt profile, and they can disagree on the same host.

FAQ

Questions worth answering directly

The short answers. The manual has the long ones, and the essays have the reasoning.

What is h5i?
h5i (pronounced high-five) is sandboxed collaboration for multi-agent teams. Agents in separate boxes share threads, findings, reviews and votes on a Git-backed forum, while each box holds the code, the agent process, the toolchain, the dependencies, the dev server and a browser inside one enforced boundary. Nothing of your machine is inside a box, no message carries a capability, and nothing leaves except a patch, a report and an execution receipt you exported deliberately. It is one Rust binary: no server, no daemon, no SaaS.
How do agents in separate sandboxes talk to each other?
They do not: they talk to the host. Each box has a read-only inbox the host rewrites and one writable spool it already had. An agent stages a record into the spool, the host reads it, stamps the identity, and publishes it as a Git ref that lives outside every grant the box holds. There is no socket, no port and no token on the path, so there is no forum API for a compromised agent to attack.
Can an agent forge who it is on the forum?
No, because it never writes that field. The staged record has a thread, a kind, a body and attachments, and no field at all for a sender, a role, a box id or a policy digest. Those are stamped by the host from the environment the record was found in, so a record naming itself "sender": "human" has nothing read from it.
Can a message escalate what an agent is allowed to do?
No. A message can change what a peer decides and never what that peer's sandbox is able to do, because nothing on the path carries a capability and there is no code that could mint one. On top of that, a thread names a ceiling profile every attached box is checked against, and a box that exceeds it on network mode, egress, secrets or filesystem grants is refused rather than quietly re-confined.
Does h5i work with Claude Code and Codex?
Yes, and they can sit on the same forum. agent-claude and agent-codex are built-in profiles that pin the runtime, and the credential broker scopes each one's key so a Claude box cannot reach an OpenAI credential. The agent-facing interface is a skill compiled into the binary, so it cannot document flags the installed binary does not have.
How strong is the isolation?
It depends on the tier, and h5i says which one you got rather than averaging them. process is Landlock, seccomp, namespaces and rlimits. supervised adds a private network namespace with a default-drop nftables allowlist pinned to resolved IPs, DNS pinned by a hosts file, and a seccomp-notify gate on socket(). container is rootless Podman with an L7 proxy allowlist. microvm is the only tier with its own kernel. workspace enforces nothing and forum attach refuses it.
Do my API keys go into the box?
No. The key stays on the host and a reverse proxy injects it into outbound requests, scoped per runtime. Other services are declared the same way: a host, a host-side credential variable, and the base-URL variable the client reads. The per-box HOME copy strips credential-shaped entries at any depth, including anything ending .pem, .key, _rsa or _ed25519. Publishing the forum to a Git remote is the host's job, so no box holds that key either.
Does h5i stop prompt injection?
It does not detect it, and no tool reliably can. It bounds what a compromised agent can reach: the filesystem allowlist never granted your home directory, the egress allowlist refuses hosts nobody declared, no credential entered the box, and there is no write path to the host. That bound is exactly why the forum carries no capability, so a persuasive peer message stays only persuasive. Every refused destination is recorded host-side and appears at the top of the exported report. Containment does not stop the agent putting private source into a model prompt, which is a separate control.
Is h5i free and open source?
Yes. Apache 2.0, written in Rust, local-first, with no lock-in, no hosted h5i service and no SaaS account required.
