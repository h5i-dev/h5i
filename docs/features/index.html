Feature Overview

A whole development environment, inside one boundary.

Sandboxing one command was the right idea at the wrong scale. An agent's work is a shell, a package manager, a build, a test run, a dev server and a browser. All of them are inside, or the boundary is decorative. One Rust binary, no daemon, no SaaS.

What is a contained agentic development environment?

A disposable environment that holds everything a coding agent needs to do real work, inside a single enforced boundary. Nothing of your machine is inside it. Nothing leaves it except through one deliberate step.

Box = workspace + agent + broker + browser + output gate.

h5i is not a provenance system and not a defence against a targeted kernel exploit below the microvm tier. It contains execution and records what actually ran.

├─ Sandboxed agent           h5i box shell
├─ Credential + net broker   .h5i/env.toml
├─ Browser inside            h5i box view

Containmentwhat the agent cannot reach, decided before it starts
h5i box . · --pr · <url> · --new
A disposable box, shaped by where the code came from
Your own repository gives you a real git worktree on its own branch, sharing the object store, so h5i box apply can land the work back locally. A URL, a pull request or --new gives you a detached box: its own repository, yours neither read nor written after creation, and the inherited origin remote dropped so the box arrives holding no network handle. The policy is resolved, written out and hashed before any state exists on disk, so an unsatisfiable request fails closed rather than leaving half a box behind.
external code can never land by momentum: apply refuses on a detached box.
isolation = workspace | process | supervised | container | microvm
Five tiers, each labelled with what it honestly claims
Landlock, seccomp and namespaces on Linux; Seatbelt on macOS; rootless Podman for portability; and a microVM with its own kernel through microsandbox. auto picks the strongest the host can run, and an explicit tier fails closed rather than downgrading, because a silent downgrade puts a claim in the record the run never had. h5i box probe runs a functional self-test rather than reading capability bits.
the tier you asked for is the tier you got, or creation refused.
[profile.X.net] egress = […]
Egress allowlists, named by OSI layer
supervised enforces at L3/L4: default-drop nftables in a private netns, DNS pinned by a hosts file, and a seccomp-notify gate on socket() that denies AF_NETLINK so the ruleset cannot be flushed from inside. container enforces at L7 with a CONNECT proxy, which binds proxy-respecting tooling only. microvm evaluates it in the guest's own network stack. Same field, three different guarantees, and h5i says which one you got.
"egress control" is never one word here: the claim is stated per tier.
[[profile.X.auth]] · h5i box secrets
Credentials that never enter the box
The model API key stays on the host; a reverse proxy injects it into outbound requests, scoped per runtime, so a Claude box cannot reach the OpenAI credential. Any other service is declared the same way: a host, a host-side credential variable, and the base-URL variable the client reads. The per-box HOME copy strips credential-shaped entries at any depth, including anything ending .pem, .key, _rsa or _ed25519.
a prompt-injected agent has no reusable token to read or exfiltrate.
Evidenceobserved from outside, stored where the box cannot reach it
h5i box export <name> --out ./review
The output gate
Three files. patch.diff, path-validated against symlink escapes, a nested .git and agent-introduced gitlinks. report.md, ordered by how much you should trust each section, with denied egress attempts first and the agent's own proposal last. receipt.json, every observed execution with the policy digest that was enforced. It refuses to overwrite a non-empty directory, and secret redaction and size caps apply to all three.
the box has no write path to your machine; getting work out is a step you take.
h5i box log · status · inspect --capture
A sealed execution receipt
An append-only JSONL log per box. The box's entire write window under its own directory is its spool; the receipt log and its payloads are siblings of that spool, outside every grant. The box stages a record and the host ingests it, so there is no path from inside to a record the host already wrote. Exits and resource usage come from the supervisor's wait4, egress from the allowlist proxy's own log.
the record is generated from observation, not from the agent's account of itself.
source: host-env-run | viewer | tee-shim | inbox-capture
Every record names who observed it
Host-observed and box-claimed evidence never blur into one number, because the lane is a required field on every record and the console labels every row with it. An agent can stage extra records or stop writing them; both are visible as a gap against host-observed exits, and h5i does not claim more than that.
you can tell testimony from observation without trusting either.
h5i ui
The box console, read-only by construction
The whole fleet on one screen: every box with its tier and status, the policy actually enforced, and a flight recorder of one row per receipt across five lanes. Red means the egress allowlist refused a destination and nothing else is ever red; amber means look at this; grey means the evidence is weak. Every route is a GET, so there is no mutating surface to guard. Loopback only, with a session token kept in memory so no box can read it.
nothing on the screen is a score, and the console cannot drive a box.
Working in itthe parts that make autonomy actually usable
agent-browser · h5i box view · h5i browser take
A browser in the box, with two interfaces
Chrome and a fresh profile live inside, so nothing you are logged into on the host is logged in there. The agent drives it; you watch the same viewport and take the controls when you want. The stream port is never published: h5i enters the box's network namespace by pid, connects from inside, and hands the socket back out. --term draws the page in your terminal and binds nothing at all.
frames flow out always; input flows in only for the control-lock holder.
h5i box cache refresh · ls · mounts
Warm dependency caches
Cold install is the difference between a twenty-second box and a four-minute one. One cache per project and ecosystem, keyed by a digest of that ecosystem's lockfiles; a cache whose key no longer matches is stale and never handed to a box. Mounted read-only, which costs nothing because every package manager falls back to fetching what it cannot find, and written only by a box with no agent inside and egress narrowed to the registries.
no mutable surface is ever shared between an agent box and anything else.
h5i skill install · show · path
The agent skill, embedded in the binary
The skill is compiled in at build time, so it cannot document flags the installed binary does not have. That matters more for agents than for people: an agent acts on stale documentation without hesitating, then reports that your tool is broken. The in-box agent gets it the same way, from the binary already in the box, so nothing is baked into an image and nothing is copied from host to box.
the documentation an agent reads is an artefact of the build, not a file that rots separately.

Use Cases

The box in action

Four workflows where containment changes what is possible, not just what is safer.

01
Review a pull request by running it
Checking out a stranger's branch used to mean handing its install scripts your shell. A detached box makes running it the cheap option instead of the risky one.
~/my-project 
$ h5i box --pr 1234
  created box pr-1234 · detached · own repository · origin remote dropped

$ h5i box shell pr-1234
box$ npm ci && npm test      # lifecycle scripts run in here, not on your machine
box$ exit

$ h5i box export pr-1234 --out ./review
$ head -6 ./review/report.md

# Denied egress
  telemetry.vendor.invalid:443   refused (not in net.egress)   x7

Seven refused connections from a branch whose description says it fixes a date-formatting bug. Read how it works →

02
Let an agent run with permissions off, safely
Inside a box, permission mode is a convenience setting rather than a boundary. The boundary is the policy that was hashed before the box existed.
~/my-project 
$ h5i box . --profile agent-claude
$ h5i box shell fix-auth
box$ claude --dangerously-skip-permissions

# it still cannot read what was never granted
box$ cat ~/.ssh/id_ed25519
cat: /home/agent/.ssh/id_ed25519: No such file or directory

# and it still cannot reach a host nobody declared
box$ curl -s https://paste.example.invalid
curl: (7) Failed to connect: refused by egress policy
03
Watch the page the agent is driving, then take over
The stream port is never published. h5i enters the box's network namespace by pid, connects from inside, and hands the socket back out.
~/my-project 
box$ agent-browser stream enable
box$ agent-browser open http://localhost:3000

$ h5i box view fix-auth          # loopback-only forward, per-box token
$ h5i box view fix-auth --term   # draw it here instead; binds nothing

$ h5i browser status fix-auth
  control: agent   refs: fresh
$ h5i browser take fix-auth      # immediate; the agent's @refs go stale

Handing control back invalidates every page reference the agent held, so it must re-snapshot before acting and acting first is refused rather than mis-clicked. The three rules →

04
Find out what this machine can actually enforce
A functional self-test, not a feature probe. The required bits can all be present while a hardened kernel still denies confined exec.
~/my-project 
$ h5i box probe
── Host isolation capabilities ──
  os           = linux
  mechanism    = landlock+seccomp
  landlock_abi = 3
  userns       = true
  seccomp      = true
  tty-injection= blocked at the kernel tiers, possible at isolation=workspace
  container    = podman
  microvm      = none

  claim workspace  satisfiable = yes
  claim process    satisfiable = yes
  claim container  satisfiable = yes (needs rootless Podman + profile container.image)
  claim microvm    satisfiable = no  (needs microsandbox `msb` + host virtualization)
  process tier runnable = yes

tty-injection is h5i measuring something it declines to assert: on Linux it is your kernel's setting, on macOS it is the Seatbelt profile, and they can disagree on the same host.
