Four shapes a box can take

h5i has one create command, and it produces materially different things depending on where the code came from. The differences are not conveniences. Each one closes a door that the other shapes need open.

By Koukyosyumei Reading time 7 min Tags Patterns · Practice · Design
The split. A box from this repository is a real git worktree on its own branch sharing the object store, so h5i box apply can land it back locally. A box from a URL, a pull request, or --new is detached: its own repository, your repository untouched after creation, the inherited origin remote dropped, and apply and rebase refused in favour of export.

Four invocations, and the interesting thing is how much they differ underneath.

~/my-project
$ h5i box .                          # this repository, at HEAD
$ h5i box --pr 1234                  # a pull request head
$ h5i box https://github.com/o/r     # an external repository
$ h5i box --new                      # nothing at all

The repo box: work you intend to keep

Pointing at your own repository gives you a real git worktree on its own branch, sharing the object store. Sharing the object store is what makes h5i box apply able to land the work back locally in one step, without going through a patch file.

Use it for the ordinary case: a feature, a refactor, a bug you are handing to an agent while you do something else. The base revision is pinned at creation, so h5i box diff keeps meaning one thing, and h5i box status tells you when the parent has moved.

This is the only shape where landing the work is a one-command operation, and that is exactly why the other three are not.

The pull-request box: somebody else's branch

--pr takes a number, a #number, or a URL, fetches refs/pull/<n>/head, and pins it. It needs only git.

And it is detached, which is four separate decisions:

  • It gets a repository of its own, so there is no shared object store and nothing it writes that your repository later reads.
  • Your repository is neither read nor written after creation.
  • The inherited origin remote is dropped, because a remote is a network handle with credentials attached and a box should not arrive holding a door nobody opened.
  • apply and rebase refuse, and point at export.

That last one is the difference between reviewing a branch and accepting it. There is no command that turns "I looked at this" into "this is in my tree" through momentum.

The clone box: code with no pull request attached

A repository URL gets the same detached treatment. This is the shape for a dependency you want to read by running, a security advisory's proof of concept, a tool you are evaluating, or anything a colleague sent you as a link.

Pair it with a narrow profile. Code you are inspecting rarely needs the network at all, and mode = "deny" is airtight and cheap, which makes any egress attempt in the report a much louder signal than it would be against a permissive allowlist.

The empty box: build from nothing

--new creates a box with a fresh repository and one empty commit. Also detached.

This is the greenfield shape, and it is more useful than it sounds. An agent asked to scaffold a project reaches for package managers, template generators and installers, which is a large quantity of network activity and downloaded code that you have no reason to trust and every reason to keep out of a repository that already contains work.

An empty box lets that happen somewhere with nothing to damage, and export gives you a patch against an empty tree, which is just the files.

The fifth shape, which has no agent in it

Worth knowing because it is the one people do not think to look for. h5i box cache refresh <ecosystem> creates a box that runs the dependency install step alone, with egress narrowed to the registry hosts and nothing else, and no agent inside.

It refuses unless the project declares a profile whose egress is the registry hosts and nothing more, and it prints that profile ready to paste rather than creating a box whose fetch could not have worked. The result is mounted read-only into agent boxes, which costs nothing in correctness because every package manager falls back to fetching what it cannot find.

The rule underneath it: no mutable surface is ever shared between an agent box and anything else.

FAQ

What is the difference between a repo box and a detached box?

A box from your own repository is a real git worktree on its own branch sharing the object store, so h5i box apply can land it back locally. A detached box, from a URL, a pull request or --new, gets a repository of its own, leaves your repository untouched after creation, drops the inherited origin remote, and refuses apply and rebase in favour of export.

Why is the origin remote dropped in a detached box?

Because a remote is a network handle with credentials attached. Leaving it in place would mean the box arrived holding a door nobody decided to open, which is exactly the kind of inherited authority the boundary exists to remove.

What is an empty box for?

Scaffolding. An agent asked to start a new project reaches for package managers, template generators and installers, which is a lot of network activity and downloaded code you have no reason to trust. An empty box lets that happen where there is nothing to damage, and the exported patch is just the files.

What is h5i box cache refresh?

A box with no agent in it that runs the dependency install step alone, with egress narrowed to the registry hosts. It refuses unless the project declares a profile with exactly that egress, and prints one ready to paste. The result is mounted read-only into agent boxes, so no mutable surface is ever shared.
