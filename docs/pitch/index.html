02 / The insight

Finding Bugs Doesn't Prove Correctness.

Testing and red-teaming can uncover vulnerabilities, but cannot establish that critical properties always hold.

TESTING & RED-TEAMING

Find Bugs ∃

Find vulnerabilities in tested executions; their absence is not a guarantee.

FORMAL VERIFICATION

Prove Properties ∀

Establish stated properties for all modeled inputs, under explicit assumptions.

Critical rules need stronger evidence: formal verification.

04 / The architecture

Write Once. Verify with Lean 4.

Axum and storage stay outside the pure Rust kernel, so application decisions can be extracted and proved. GPU execution is an optional optimization.

Rust / parallel/kernel/src/lib.rs · pure kernel
pub fn push_rule(event: &[u8], pattern: &[u8],
    display: &[u8], members: u64,
    minimum: u64, maximum: u64, power: u64,
    required: u64, enabled: bool,
    require_display: bool) -> u32 {
    if !enabled { return 0; }
    if power < required { return 0; }
    if members < minimum
        || members > maximum { return 0; }
    if !glob(event, pattern) { return 0; }
    // display-name check omitted
    1
}
No I/O and no allocation: Axum and storage adapters stay outside.

05 / Formal verification

Prove Critical Application Properties

Rust / kernel/src/lib.rs
fn delete(user: u64, s: &Snapshot,
          id: u64) -> Outcome {
    match find_post(&s.posts, id) {
        None => Err(Error::NotFound),
        Some(p) => {
            if p.author == user
                || is_moderator(&s.moderators, user) {
                Ok((one(Write::DelPost(id)),
                    Reply::Done))
            } else {
                Err(Error::Forbidden)
            }
        }
    }
}
